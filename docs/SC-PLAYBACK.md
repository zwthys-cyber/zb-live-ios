# SC 原画播放适配

SC 房间列表与播放元数据仍通过原服务取得；SC 视频清单、初始化信息和视频分片直接从原始 CDN 读取。AVPlayer 使用设备上绑定到 `127.0.0.1` 的播放代理，完成清单规范化和请求头转发，不经过原服务的视频中转。

## 原画选择

服务端 `platform_code=sc_*` / `stripchat` 与数字 `chat_room_id` 用于构造 SC 原始主清单。主、备 CDN 分别尝试；收藏重开和重新连接重新解析地址。粘贴已识别的 SC CDN 链接也会进入同一处理流程。

最高档按主清单声明的像素总数、码率排序，保留真实的 source 原画，包括竖屏、960p 及高于 1080p 的档位。不把 URL 文件名当作实际视频分辨率，也不把修改 URL 中的 `480p` 当作成功升级。

## MOUFLON

从当前主清单的 `PSCH` 标签中选择应用支持的公开播放器描述符，向选中的媒体清单附加 `psch` / `pkey`。只使用该主清单实际公布的描述符，不发送用户账户或会话凭据。

v1 还原 `FILE` 的文件名；v2 还原 `URI` 中的反转 Base64 标记：与 SHA-256(公开解码描述符) 循环异或，恢复真实分片路径，替换对应的 `media.mp4` 占位行。初始化信息、媒体序号与时间保留，低延迟局部分片由既有 HLS 规范化逻辑处理。

不能只删除 MOUFLON 标签：未还原的占位地址没有真实视频。客户端也拒绝 `MOUFLON-ADVERT`，即使它的 HTTP 状态是 200。播放期间描述符失效时重新读取主清单并协商一次；仍失败则显示错误，允许用户重新连接。支持的描述符全部轮换后需要更新应用，当前没有下载执行外部脚本的机制。

公开协议资料：[StreaMonitor 的 SC 实现](https://github.com/lossless1024/StreaMonitor/blob/master/streamonitor/sites/stripchat.py)、[公开描述符对照数据](https://github.com/kesamom/stripchat_mouflon/blob/main/stripchat_mouflon_keys.json)。Swift 解析和地址还原逻辑独立实现；自动测试使用独立的合成描述符。

## 验证

2026-10-20，指定的公开房间：原始主清单返回 720×960 source、360×480 和 180×240；原服务中转所用的 CDN 清单只有后两档。原画协商成功后，初始化 MP4 的视频轨道确认为 720×960，地址还原后的分片返回 HTTP 200，包含有效 `moof` / `mdat` 盒。没有把无协商时返回的 640×480 占位视频计为原画验证。

自动化覆盖实际画质排序、竖屏 source、4K、MOUFLON v1/v2 独立向量、未知描述符、损坏地址、HTTP-200 占位清单及播放中描述符续期。模拟器界面测试经本机代理播放合成清单，验证实际 AVPlayer 就绪与收藏重开，所有自动测试都不访问真实直播内容。

SC 账户／收费房间授权未接入。用户设备仍须能够访问原始 CDN，最终播放也取决于其网络和系统支持的编码。没有在用户的 iOS 17.0 真机上实测。
